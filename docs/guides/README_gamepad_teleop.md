# 双模式 Xbox 类手柄控制预留层

当前版本已实现 DualSense `evdev` 输入读取、输入归一化、按键映射、模式状态机
、底盘 ROS1/TCPROS 输出及机械臂关节直连点动输出。命令行输入监视工具仍只打印采样。
GUI 默认不产生运动，必须连续点击两次开启按钮；第一次只显示“你确认开启测试么？”，
第二次确认且当前模式所用输入处于中位后，才连接对应输出。关闭按钮只需点击一次。
底盘关闭时连续发送零速，机械臂关闭时由远端看门狗保持当前关节并恢复轨迹控制器。

## 状态机

```text
CHASSIS --L3+R3 双击--> ARM_RETURNING --返原位成功--> ARM
ARM    --L3+R3 双击--> ARM_RETURNING --返原位成功--> CHASSIS
任一普通模式 --Circle 双击--> ARM_RETURNING --返原位成功并恢复控制--> 原模式
任一普通模式 --Circle 长按3秒--> ARM_RETURNING --返原位成功且控制保持关闭--> 原模式
```

进入 `ARM` 的同一输入帧先输出底盘停止，不透传机械臂运动。离开 `ARM` 的同一帧
先输出机械臂停止和回原位请求。`ARM_RETURNING` 中所有手柄运动量为零；回原位失败
时继续锁定底盘。

## 映射

底盘模式使用左摇杆 X 转向、R2 前进油门、L2 倒车油门。速度为两个扳机归一化
行程之差；两者同时按下时互相抵消。两个扳机松开后，每个输入周期都会输出零
线速度和零角速度，因此左摇杆即使没有回中也不会让底盘原地旋转。底盘为差速
结构，横向速度固定为零。

机械臂模式使用固定直连映射：方向键左右控制 J1，方向键上下控制 J2，左摇杆上下
控制 J3，R1/L1 控制 J4 顺/逆时针，右摇杆上下控制 J5，R2/L2 控制 J6 正/反转。
Cross 切换夹爪，Triangle 开启/关闭语音控制。Circle 双击仅返原位并在成功后恢复
原控制；Circle 持续按住 3 秒会关闭控制并执行
返原位；L3+R3 双击切换模式。两种确认操作都会先停用其他输出，再请求返原位，
返程成功后才恢复原模式或进入目标模式。L3+R3 双击本身就是模式切换的完整确认；
返原位成功且目标模式所用输入都回中后，GUI 自动启用目标模式，不再要求额外点击
两次开启按钮。Circle 长按 3 秒会先关闭运动控制再执行返原位，完成后控制保持关闭。
所有返原位路径都会在运动前明确闭合夹爪，并在到达后用实时关节反馈再次确认闭合；
已经闭合时不会发送切换命令，因此不会因内部状态不同步而反向打开。

原位接近运动学奇异区，因此手柄模式不再求解笛卡尔 IK，也不要求多个关节共同
保持末端位置和方向。手柄关节速度上限为 0.18 rad/s，低于 URDF 关节速度上限。
每个候选六轴状态先经 MoveIt 插值碰撞校验；碰撞、校验服务不可用
或到达带 0.02 rad 余量的关节限位时不发布候选点，保持最后已验证安全的位置。
用户仍可操作反方向退出被阻挡区域。

## 纯软件干运行

每行输入一个归一化 JSON 手柄采样，程序逐行输出控制意图：

```bash
PYTHONPATH=. python3 tools/gamepad_teleop_dry.py <<'EOF'
{"right_trigger":0.8,"left_x":0.3}
{"left_stick_button":true,"right_stick_button":true}
{}
{"right_x":0.5,"right_trigger":0.4,"dpad_y":1,"a":true}
{"a":false}
{"y":true}
EOF
```

测试命令：

```bash
PYTHONPATH=. pytest -q tests/test_gamepad_teleop.py
```

## DualSense 输入检查

驱动安装且手柄完成配对后，可用以下命令只检查输入：

```bash
PYTHONPATH=. python3 tools/dualsense_input_monitor.py
```

DualSense 同时按下左右摇杆（`L3+R3`）切换模式；`Options` 当前不分配功能。
系统启动后 GUI 自动监听手柄。连续两次同时按下并松开 `L1+R1+L2+R2`，随后松开
全部按键和扳机、让摇杆回中，即可通过同一安全检查开启当前模式的真实控制。
Cross/Circle/Triangle 分别映射为当前抽象层的 A/B/Y。该工具没有机器人输出依赖，
输入监视工具退出或手柄断连时不会产生运动命令。

从应用程序菜单打开 `DualSense Input Test`，或运行：

```bash
PYTHONPATH=. python3 tools/dualsense_input_gui.py
```

GUI 会显示 Square/Triangle/Circle/Cross、L1/R1、L2/R2、L3/R3、Create、
Options、PS、触摸板按压、双摇杆、模拟扳机、方向键、触摸坐标以及六轴运动
传感器。每个按键按过一次后会保留绿色勾号，顶部计数到 `15 / 15` 表示包括
麦克风静音键在内的实体按键均已测试。

GUI 使用标准 `rospy` 发布器连接安全仲裁器的手柄入口 `/gamepad/plt_cmd_vel`。R2 前进、L2 倒车，左摇杆 X 直接
决定转弯量。摇杆进入 0.10 死区后 `angular.z` 每 20 ms 明确发送为零，因此在
油门保持不变时左右轮恢复同速直行。手柄断开、发布异常、关闭控制或关闭窗口
都会发送停车命令。L3+R3 的第二次确认会先关闭当前输出并执行碰撞校验的返原位轨迹，
成功后才切换模式。机械臂模式经 GUI 二次确认后连接 OrangePi 的看门狗 UDP 桥；
桥以当前六轴反馈播种位置控制器，避免控制器切换时复用陈旧命令。控制周期为
20 Hz，关节段以不大于 0.015 rad 的步长插值送入 MoveIt `/check_state_validity`。
MoveIt 场景使用关闭滑块状态的真实车体碰撞模型，并为
`top_chassis_link` 保留 1 mm 建模误差余量。URDF 标定本身已提供原位约
5 mm 的物理间隙，不再重复膨胀 5 mm。
桥会检测原 QP/MoveIt 任务是否活动，避免两套控制同时向机械臂输出。命令停止
0.20 秒时速度归零，心跳停止 0.60 秒时恢复轨迹控制器。按钮自动按压流程及其
QP 配置不变。

厂商 `velocity_smoother` 及其启动文件保持不变。GUI 获得租约时，底盘侧
`chassis_smoother_runtime_manager.py` 用 `SIGSTOP` 暂停厂商 smoother，再将手柄
速度发布至 `/plt_cmd_vel`，避免两个发布者交错发送非零与零速。关闭控制、手柄
断连、程序异常、命令中断 0.25 秒或心跳超过 0.60 秒时，管理器先连续发送零速，
然后用 `SIGCONT` 恢复原厂 smoother。管理器重启时也会先恢复厂商进程。续租心跳
由独立后台线程发送；首帧允许 3 秒连接宽限，收到首帧后执行严格的 0.60 秒超时。

每次运行的 `control_journal.jsonl` 会分别记录手柄命令、管理器实际发布的
`/plt_cmd_vel`、`/odom` 和底盘控制板反馈的 `/RosAria/lr_speed`。监视器固定连接
`/gamepad_smoother_runtime_manager`，避免多发布者时误读被暂停的原厂 smoother。
厂商源码、二进制和 launch 文件均不修改。

配置、端口、速度限制和确认窗口均写在 `gamepad_teleop.yaml`。手柄桥只新增独立
服务和脚本，不修改厂商底盘、机械臂、smoother 或启动文件。
