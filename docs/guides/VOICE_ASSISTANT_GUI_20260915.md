按钮含义：

- **本项完成后暂停**：当前按钮按压、等待熄灭及归位全部结束后暂停，不启动下一项。
  按钮一直亮着时仍遵守原等待规则；如需立即停止，用“立即终止并归位”。
- **继续剩余任务**：明确确认后重新检查执行条件，从剩余项继续；不能修改本组已保存的按钮顺序。

- **保存核验**：选中一条记录，填写“未核验 / 已按亮 / 未按亮”；保留人工核验轨迹，不覆盖程序原判定。

## 运行入口

- 安全预览：`tools/launch_voice_assistant_gui.sh`
- 机器人执行：`tools/launch_voice_assistant_gui_execute.sh`
- 桌面上分别提供“优小妹语音助手（安全预览）”和“优小妹语音助手（机器人执行）”。

安全预览会运行本地 SenseVoiceSmall int8 和完整对话状态机，但不会发送机器人指令。机器人执行入口带有生产代码要求的两项物理运动参数。当前语音路径不调用 Whisper，也没有 Whisper 或旧 Paraformer 自动回退。

GUI 启动时语音呼叫默认关闭。聊天记录上方始终显示“开启语音”按钮和手动指令区。手动输入支持 `15`、`十五楼`、`按第十五层`、`送外卖到15楼`，点击“执行任务”或按回车即可执行；点击“开启语音”后才会识别中文唤醒词“一二三”和任务指令，再次点击会关闭语音识别。

界面使用系统 `/usr/bin/python3` 的 Xft Tk 和 `Noto Sans CJK SC` 直接渲染中文，并把 Tk 缩放与当前 Xft 设置统一为 96 DPI。流式 ASR 和机器人后端由 `piper-handeye` Conda Python 启动。Conda 自带的 Tk 只能看到旧式 X11 位图字体并会回退为 `fixed`，不再用它渲染 GUI。需要适配其他显示器时可在启动前设置 `YOUXIAOMEI_UI_DPI`（允许 72–384）。

## 对话与执行链

1. SenseVoiceSmall 准确收到中文“一二三”时，GUI 显示“优小妹：在的”。连续 10 秒没有听到话时显示“请给我任务”并继续等待；连续 20 秒无输入时清除唤醒并显示“任务未下达”。期间听到任何一句话都会重新开始静默计时。不会把 `123` 或其他近似文本替换成唤醒词。
2. 说“没事了”会清除本次唤醒，GUI 回复“好的”，不会停止已经运行的机器人任务。
3. 完整命令被接受并开始执行后，语音识别自动关闭并清空缓存。
4. Silero VAD 使用 1.0 秒句尾静音，允许句中约 1 秒的停顿。
2. 用户说完整句式“送外卖到15楼”，GUI 显示最终识别文本。因为当前按用户要求只用一个模型，运动入口依靠精确唤醒名、严格整句语法、1–16 范围检查和重复抑制关门；只容许模型漏掉句尾“楼/层”这一种归一化。模型不提供校准置信度，日志不会虚构一个分数。
3. 执行链固定为：`run_voice_assistant_gui.py` → `run_voice_streaming.py` → `CommandDispatcher` → `run_button_batch.py` → `run_button_light_closed_loop.py`。
4. GUI 只消费 JSON 事件，不直接控制机械臂或底盘。
5. 手动输入通过 stdin JSON 控制通道进入同一个语音后端和 `CommandDispatcher`，因此手动任务与语音任务共享任务互斥和完成状态。
6. 语音开关变化时同时重置 VAD、识别流、唤醒窗口并清空麦克风队列，关闭期间不解码，重新开启后不会执行旧语音。
7. 每次 GUI 会话的后端 JSON 事件写入 `voice_gui_runs/<时间>.jsonl`，包括被界面过滤的非指令转写。

## 麦克风噪声与端点切分

生产链使用 sherpa-onnx 官方 Silero VAD 先隔离语音，再把完整短句送进常驻 SenseVoiceSmall。Silero 阈值为 0.55，最短语音 250 ms，尾静音 350 ms。端点后的稳定结果才进入聊天和命令状态机。

依据：

- sherpa-onnx 官方支持 aarch64/Jetson、本地流式 ASR 和 Silero VAD：https://github.com/k2-fsa/sherpa-onnx
- sherpa-onnx Silero VAD 文档与模型：https://k2-fsa.github.io/sherpa/onnx/vad/silero-vad.html
- 2025 年非语音诱发 Whisper 幻觉研究在约 30 万段非语音样本上验证问题，并报告 Silero VAD 显著降低幻觉和 WER；单纯语音增强不一定解决幻觉：https://arxiv.org/abs/2501.11378
- RNNoise 是成熟的实时语音增强备选，但本问题首先是把非语音送入 Whisper，而非仅提高听感，因此先采用 VAD，避免额外失真和 ARM 依赖：https://arxiv.org/abs/1709.08243

本机历史录音回放结果：SenseVoiceSmall 对两段目标语音均输出“十五楼”，完整任务原样输出“送外卖到十五楼”，不经过词语替换。完整任务解码 0.187 秒、RTF 0.055；常驻模型加载约 2.70–2.88 秒。该结果只覆盖本机少量历史录音，不能代替后续多说话人、多楼层准确率测试。

## 固定反馈

- 唤醒：`在的`
- 启动任务：`正在执行`
- 按钮未亮并进入重试：`尝试再次按压`
- 视觉安全检测到遮挡：`检测到异物，暂停任务`
- 遮挡清除：`异物已移除，继续任务`
- 任务进程退出码为 0：`任务已完成`
- 任务进程异常退出或视觉安全监督失败：`任务失败`

关闭 GUI 时会向语音后端发送 SIGINT。若机器人任务仍在执行，语音后端先调用独立停止桥，再终止任务进程组。
