# 顶盖滑块控制接口调查（2026-09-28）

本次仅作只读调查；未调用控制服务、未发布运动话题、未移动滑块或机械臂。

## 已确认

- 底盘 ROS Master 位于 `192.168.168.100:11311`。Android 设备 `192.168.168.110` 已注册 `/android/remotemanager` 与多个 `/listener` 节点；`/android/remotemanager` 当前没有公开话题订阅、发布或服务。该设备未开放 SSH/ADB 端口。
- 底盘当前 ROS 节点、话题、服务和厂商 `custom_msgs_srvs` 定义中，未发现明确的顶盖滑块开合命令或开/关到位状态。`/chassis_sensors_info` 的 `AllStateInfo` 不包含滑块字段。`/chassis_reply` 与 `/SWJ/switch` 在只读等待期间未发出可解读的状态。
- `/auto_container_manager/auto_container_cmd_srv` 属于对货柜标记定位和底盘靠近任务。其厂商程序包含 `Start go container`、位姿校准、激光标记等逻辑，不能当作顶盖滑块驱动接口。
- `chassis_server_new` 公开的电机状态字段是左右驱动轮；现有 `DoorStatePoseInfo` 与酒店门检测逻辑相关。未找到滑块电机控制命令。
- OrangePi `192.168.168.120` 的机械臂 ROS 图也没有滑块相关节点、话题或服务。
- 机械臂 MoveIt 当前使用关闭滑块的 `top_chassis_closed.STL` 碰撞模型。滑块若打开，必须在机械臂运动前切换或更新相应碰撞几何。

## 尚未确认

- 滑块是电机、推杆、电磁机构还是手动机构驱动，以及驱动板连接到哪台计算机或控制器。
- 磁铁开/关信号的实际接入点与协议。物理开关可能是二值输入，但当前可访问的 ROS 消息未暴露已映射的滑块布尔状态。
- Android App 是否通过本地 GPIO、串口、厂商私有协议或其他通道直接控制滑块。设备的 TCP `45001` 端口已有底盘 `/rosout` 连接，属于 ROS 通信，不能将其推定为滑块控制端口；泛用 ROS 字符串服务也不能直接当作开合接口。

## Ubuntu 板非车轮电机排查（同日补充）

- 正在运行的 `chassis_server_new` 独占 `/dev/ttyTHS1`，其 ROS `MotorState` 仅包含左右轮与恢复状态；`/dev/ttyTHS2` 被 IMU 使用。`rduc_cpp` 占用扩展串口 `/dev/ttysWK1`，其程序和产测脚本将 GPIO39、GPIO66 分别标为电刹控制和电刹反馈。`/dev/ttysWK0` 当前无人占用。
- Ubuntu 的 USB 设备仅列出相机和集线器，没有发现独立的 USB 电机控制器。I²C 枚举中有 WK2168 串口扩展器和系统外设，没有标识出的电机驱动芯片；当前也没有活动 CAN 网络接口或被用户进程占用的 I²C/SPI/GPIO 字符设备。
- 已导出的 GPIO 中，厂商脚本明确将 168 用于 ZigBee、63 用于 IMU、12/38 用于深度相机、39/66 用于电刹；151 为 USB 供电，152/15/232 在启动时被置高，但没有查到运行时滑块控制逻辑。不能仅凭引脚电平推断其连接负载。
- 已安装的底盘 ROS 程序和运行进程未找到滑块专用电机节点。`/up_and_down_pile_status` 来自充电管理节点，属于充电桩流程，不能用作滑块控制。

以上只说明滑块电机没有通过目前发现的 Ubuntu 驱动公开；电机仍可能由 Android 板、独立控制器或底盘控制板的私有通道驱动。

## 接入条件

需要确认滑块执行机构和控制板型号、接线或厂商命令协议；若 Android App 中有现成开合功能，可从该 App 的安装包或厂商接口文档追踪命令。确认后先实现只读状态查询与显式开/关命令，加入到位反馈、超时和机械臂碰撞模型联动。实机动作测试须等用户另行通知。
